## Automatic browser capture: already implemented, with limits

The extension defaults to automatic sync after pairing. `extension/content.js`
checks every five seconds, requires a stable conversation URL and identical text
across two checks, skips known streaming indicators, suppresses unchanged captures,
and backs off failed submissions for 30 seconds. The background worker sends an
authenticated request to the loopback daemon. Pairing and the pause toggle are in
the popup. No click is needed for each conversation.

This is **automatic capture of visited, visible chats**, not account-wide or
always-running archival:

- Hidden tabs are skipped. A chat may be missed if closed before capture, if the
  daemon is unavailable, or if the browser suspends the page.
- The daemon must remain running. Installers do not install a login service.
- The userscript implements manual capture only.
- DOM capture does not guarantee collapsed/virtualized turns, attachments,
  citations, tool details, or complete streaming detection.
- Perplexity extracts only one question/answer. Claude's generic fallback invents
  a user turn from the page title; Gemini's fallback guesses roles by position.
  Those fallbacks should not be treated as faithful archival evidence.
- A changed DOM selector can silently reduce capture quality. Live logged-in
  provider layouts have not been verified in this review.

Added the missing bare `perplexity.ai` host to extension permissions and content
script matching. Existing `www.perplexity.ai` support remains. Added explicit
manifest and hidden-tab/resume assertions to the browser tests.

## Installer findings addressed

| Finding | Change and verification |
| --- | --- |
| Application replacement preceded launcher creation, so a launcher failure could leave a partial upgrade. | Stage launchers first; replace them atomically and restore the previous app on replacement failure. Linux injected-failure test passes; Windows locked-launcher regression added. |
| Existing launcher files or symlink destinations could be overwritten. | Reject unrelated launchers and non-regular targets; recognize legacy generated launchers for upgrades. Linux preservation tests pass; Windows preservation test added. |
| Unix launcher reselected Python on every run, potentially losing the interpreter whose SQLite was checked. | Resolve and retain the validated interpreter; check version and FTS5 together while selecting candidates. Windows likewise resolves the actual interpreter behind `py`. |
| Current directory and inherited PYTHONPATH could shadow the installed package. | Use Python isolated mode and insert only the application directory explicitly. Linux conflicting-package test passes. |
| Unix PATH guidance ignored custom bin directories. | Print the actual shell-quoted directory. Reject bin directories nested in the application tree. |
| Windows launcher encoding and shell expansion could corrupt paths; PATH checks used substring matching. | Explicit console encoding, delayed expansion disabled, unsupported paths rejected before replacement, exact PATH-entry comparison, optional suppression of persistent PATH edits. Windows runtime checks remain outstanding. |
| Git-free download and Windows installer lacked dedicated runtime regressions. | Added an offline tar-download test and three Windows-only tests, automatically discovered by the existing Windows test job. |
| Quick-install documentation implied universal setup and omitted the installed extension location. | Document OS-specific paths, prerequisites, overrides, interpreter lifetime, pairing, daemon lifetime, upgrade refresh, and WSL/Android limits. |

Application backups remain available after successful upgrades. These are staged
updates with rollback for ordinary operation failures, not crash-safe transactions
across multiple filesystems; concurrent installers and power-loss recovery are not
verified. No existing installation or user PATH was changed during testing.
